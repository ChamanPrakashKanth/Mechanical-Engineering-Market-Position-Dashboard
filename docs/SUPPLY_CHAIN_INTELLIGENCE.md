# Intelligence publishing and supply-chain evidence

`python scripts/generate-intelligence.py` builds industrial evidence from `industrial/reviewed-records.json`, rebuilds AI evidence through its existing generator, generates eight supply-chain maps from `supply-chain-intelligence/reviewed-chains.json`, and updates intelligence sitemap URLs. Shared page rendering and structured metadata live in `scripts/intelligence_common.py`. Edit reviewed source registries and templates, not generated pages.

The industrial migration corrects 44 undated publication fields to null with `publishedUnknown: true`. Access dates remain distinct. Publication upper bounds retain explicit labels. Original 68 event IDs, dates, knowledge dates and stage transitions are preserved; the November 7 metadata correction does not imply capability progress. The historical controls and the single entered material-vulnerability record remain supported. Named cards display facility-scoped measures instead of anonymous dots. Existing routes and query parameters remain valid.

Supply-chain scope covers semiconductors, battery materials/cells, solar PV, grid transformers, aerospace hot sections, pharmaceutical manufacturing, robotics and CNC machine tools. Sources establish context and process descriptions; graph edges are explicitly editorial engineering relationships, not commercial contracts. Manufacturing overlays use the industrial baseline, with its own dated evidence. Uncovered nodes, unassessed inputs, missing inventory and unknown approved substitutes are never treated as resilience. Substitution is an explicit complete/immediate scenario assumption. Exports retain sources, dates, scope and assumptions.

The three hubs and 67 dedicated capability/chain pages expose static HTML, visible direct answers, source citations, individual canonical URLs, breadcrumbs, accurate WebPage/BreadcrumbList metadata and Dataset/DataDownload metadata on the dataset hubs. Page metadata matches visible content; no ratings, rankings, independent-audit claims or FAQ rich-result promises are fabricated. Social metadata uses the existing site cover. `llms.txt` is a reading aid, not a requirement or guarantee for AI search inclusion. Robots remain crawlable. Ranking and answer-engine citations are external outcomes, not deployment checks.

Publishing must include `industrial/`, `ai-intelligence/` and `supply-chain-intelligence/`; the workflow regenerates before validation. The sitemap manifest is `intelligence-pages.json`. The root homepage links all three hubs, and capability pages link contextually to relevant chain maps. Canonicals preserve current hub URLs.

Checks: `npm test`, then prepare static sources, integrate Fieldnotes and run `check:pages`, `check:links`, `check:orphans`. Browser QA covers historical states, dates, filters, country overlays, disruption propagation, links and source details. No new accounts, API keys, tracking services or paid gates are required.
